# PRD: Mutual Fund FAQs (Facts-Only Q&A) RAG Chatbot

## 1. Goal

Create a RAG-based FAQ assistant that answers factual questions about a specific set of mutual fund schemes using only official public sources. Answers must include exactly one source citation and the assistant must refuse non-factual/advisory queries.

## 2. Target Users

- Retail investors comparing mutual fund schemes (facts, not advice)
- Support/content teams answering repetitive MF FAQs

## 3. In-Scope Features

- Curated corpus (1 AMC, 3–5 schemes). Target: SBI AMC — SBI Flexicap Fund, SBI Large Cap Fund, SBI ELSS Tax Saver Fund, SBI Small Cap Fund, SBI Balanced Advantage Fund. These five campaign pages are the starting point; individual facts (expense ratio, exit load, minimum SIP, lock-in) often sit on a scheme factsheet or SID rather than the landing page, so the corpus may **add** other official pages from the same AMC / SEBI / AMFI as needed. Only official domains are permitted.
- RAG pipeline: Ingestion (Load → Chunk → Embed → Store) + Query (Embed question → Retrieve top chunks → LLM → Answer). Persisted vector store.
- Answers are factual (expense ratio, exit load, minimum SIP, ELSS lock-in, riskometer, benchmark, how to download statements, etc.). Each answer ≤ 3 sentences, includes one clear citation link, and shows "Last updated from sources: <date>". The date is taken from the source's fetch timestamp, not generated by the model.
- Guardrails: refuse opinion/portfolio advice with a polite facts-only message and a relevant educational link. Refuse performance-comparison questions and point to the official factsheet instead. Refuse and do not retain any query containing PII.
- Tiny UI: welcome line, 3 example questions, note "Facts-only. No investment advice." and a disclaimer snippet.
- Persisted ChromaDB (ingest once), local embedding model (sentence-transformers/all-MiniLM-L6-v2), Groq LLM via .env.

## 4. Out-of-Scope Features

- Portfolio advice, recommendations, buy/sell opinions, performance prediction/comparison (must link to official factsheet if asked).
- Handling PII (PAN/Aadhaar/account/OTP/email/phone) — not accepted/stored.
- Using third-party blogs, screenshots of app back-end, or any non-official sources.
- Making performance claims.

## 5. Example User Questions

- "What is the expense ratio of SBI Flexicap Fund?"
- "What is the lock-in period for SBI ELSS Tax Saver Fund?"
- "What is the exit load for SBI Large Cap Fund?"
- "What is the minimum SIP amount for SBI Small Cap Fund?"
- "What is the riskometer and benchmark for SBI Balanced Advantage Fund?"
- "How do I download my capital-gains statement for SBI ELSS?"
- "Where can I download the latest factsheet for SBI Flexicap Fund?"
- "Is there an exit load if I redeem SBI Large Cap Fund units after 1 year?"
- "What is the benchmark index for SBI ELSS?"
- "Where can I find the KIM/SID for SBI Balanced Advantage Fund?"

## 6. Success Criteria

- Working prototype (app or notebook) with the UI requirements.
- Every factual answer includes exactly one source citation link and is ≤ 3 sentences.
- Advisory/opinion queries correctly refused with a polite facts-only message and relevant educational link.
- Ingestion pipeline produces inspectable chunks saved to a readable .txt file (with chunk size, overlap, metadata documented).
- ChromaDB persisted to disk; embeddings use all-MiniLM-L6-v2 consistently.
- Groq API key stored in .env, not committed. No PII accepted/stored.
- Deliverables complete: source list (CSV/MD of every official URL used, starting from the 5 campaign URLs in the brief), README (setup, scope, known limits), sample Q&A (5–10 with answers + links), disclaimer snippet, and demo link/video (≤ 3 min) if hosting not possible.

## 7. Constraints

- Free-tier tools only.
- Runs locally.
- Deployable to Render.
- Embedding: sentence-transformers/all-MiniLM-L6-v2 (384-dim, local, no API key).
- Vector DB: ChromaDB (persisted).
- LLM: Groq (key in .env, never committed).
- Public official sources only; no third-party blogs, no backend screenshots.
- No PII; no performance claims/comparisons.
- Answers ≤ 3 sentences; include "Last updated from sources: ...".
- Chunking: agent decides (inspects data), documents size/overlap/metadata, saves all chunks to a readable .txt.
