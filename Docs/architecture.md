# Architecture: Mutual Fund FAQs RAG Chatbot

Derived from [PRD.md](./PRD.md). This document covers the components, the end-to-end data flow, the tech stack, the folder structure, and the query-path diagram.

---

## 1. Components

| # | Component | Responsibility | Key files |
|---|-----------|----------------|-----------|
| 1 | **Config** | Loads env vars (`GROQ_API_KEY`), central constants (model ids, chunk size, top-k), and the **official domain allow-list** (`sbimf.com`, `sebi.gov.in`, `amfiindia.com`). Allow-listing is enforced at the *domain* level, not by pinning exact URLs. No secrets in code. | `config.py` |
| 2 | **Loader** | Reads the curated URL list from `data/sources.csv`, rejects any domain not on the allow-list, strips boilerplate, writes clean text to `data/raw/`, and writes a machine-generated fetch log to `data/ingest_manifest.csv`. `data/sources.csv` stays hand-edited — it is a graded deliverable and must not be rewritten by the pipeline. | `ingest/loader.py` |
| 3 | **Chunker** | Inspects the loaded text, splits it into retrieval-sized chunks, attaches metadata, writes all chunks to an inspectable `data/chunks.txt`. | `ingest/chunker.py` |
| 4 | **Embedder** | Wraps `sentence-transformers/all-MiniLM-L6-v2` (384-dim, runs locally, no API key). Used for **both** chunk vectors and question vectors. | `ingest/embedder.py` |
| 5 | **Store (ChromaDB)** | Persists embeddings + metadata to `data/chroma/`. Ingestion runs once, not on every restart. | `ingest/store.py` |
| 6 | **Retriever** | Embeds the user question with the same model, runs similarity search, returns top-k chunks with their source metadata. Applies a scheme metadata filter when the question names a scheme. | `retrieval.py` |
| 7 | **Guardrails** | Pre-LLM router. Classifies the query as `factual`, `advisory`, `performance`, or `pii`, and short-circuits non-factual classes to a polite facts-only message + educational link. Also a post-check that every factual answer carries exactly one citation. | `guardrails.py` |
| 8 | **Generator** | Calls Groq with a prompt that enforces the answer contract: ≤ 3 sentences, exactly one source link, `Last updated from sources: <date>`, no advice, no performance claims. | `generator.py` |
| 9 | **UI** | Streamlit app: welcome line, 3 example questions, "Facts-only. No investment advice." note, disclaimer snippet, chat input. | `app.py` |
| 10 | **Pipeline runner** | Orchestrates ingest end-to-end: load → chunk → embed → store, and reports counts. | `ingest/run_ingestion.py` |

## 2. Data Flow

### 2.1 Ingestion (run once, offline)

```
Official URLs (data/sources.csv, domain-allow-listed)
        |
        v
   [LOAD]  fetch + HTML -> clean text
        |
        v
   data/raw/*.txt  +  data/ingest_manifest.csv
        |
        v
   [CHUNK]  split with metadata -> data/chunks.txt  (inspectable)
        |
        v
   [EMBED]  all-MiniLM-L6-v2 -> 384-dim vectors
        |
        v
   [STORE]  ChromaDB -> data/chroma/  (persisted)
```

### 2.2 Query (per user question)

```
Question
   |
   v
[GUARDRAILS] -- advisory / performance / PII --> refusal + educational link (no LLM)
   |
   v (factual)
[EMBED question]  same all-MiniLM-L6-v2
   |
   v
[RETRIEVE]  ChromaDB top-k + scheme filter
   |
   v
[CONTEXT]  top chunks + one source URL
   |
   v
   [GENERATE]  Groq LLM  (no dates, no advice, no returns)
   |
   v
[POST-CHECK]  citation present? length <= 3 sentences?
   |
   v
[APPEND]  "Last updated from sources: <fetched_at>"  (app code)
   |
   v
Answer in UI
```

**The date is appended by app code, never generated by the LLM.** The value comes from the `fetched_at` metadata of the cited chunk. Asking a model to state a date is an invitation to hallucinate one, and a wrong "last updated" line is exactly the kind of unverifiable claim this project must not make.

### 2.3 Chunking strategy (proposed, to be validated against the loaded text)

- **Why:** the corpus is FAQ/factsheet prose plus small fact tables (expense ratio slabs, exit-load slabs, minimum SIP, lock-in). Questions are short and fact-seeking, so small, self-contained chunks retrieve more precisely than large overlapping windows, and a missed chunk wastes less context.
- **Size:** `max_chunk_words = 160`, `overlap_words = 30`, **and** a hard `MAX_EMBED_TOKENS = 256` ceiling. The word limit alone is not sufficient: the original estimate of "≈160 words ≈ 200 tokens" holds for ordinary prose but not for the SID tables, where 160 words of NAV codes and dates measured **470 tokens** (500 of 2,689 chunks). Word and token limits also conflict, since 160 single-token words can exceed 256 tokens while 256 tokens of prose can exceed 160 words, so `chunker._enforce_limits` alternates between them until both hold.
- **Split order:** section heading → paragraph → sentence. Split on natural boundaries first; fall back to sentence-level packing only when a paragraph exceeds the limit.
- **Tables:** keep the header row attached to its rows; an exit-load slab or expense-ratio line stays as one atomic chunk so it is never cited without its column meaning.
- **Metadata per chunk:** `chunk_id`, `scheme`, `doc_type` (factsheet / KIM / SID / FAQ / fees / riskometer / statement guide), `source_url`, `page_title`, `section`, `fetched_at`.
- **Auditability:** every chunk is also written to `data/chunks.txt` with its metadata, so the corpus can be reviewed without running the vector store.

### 2.4 Source list policy

- `data/sources.csv` is **curated by hand** and is a graded deliverable. The pipeline reads it and never rewrites it.
- The "official sources only" constraint is enforced at the **domain** level via `config.ALLOWED_DOMAINS`, not by pinning the 5 exact URLs. This matters: the campaign URLs in the brief are landing pages, and the specific facts the demo needs (expense ratio slabs, exit load, minimum SIP, lock-in) often live on a scheme factsheet or SID rather than the landing page. You may **add** an official URL when a fact is missing; you may never add a non-official one.
- The loader writes results to `data/ingest_manifest.csv` (url, http status, bytes, fetched_at, chunk count) so you can see at a glance what loaded, what came back empty, and what needs a replacement URL.

## 4. Tech Stack

| Layer | Choice | Notes |
|-------|--------|-------|
| Language | Python 3.14 | Free, runs locally, deployable to Render. |
| UI | Streamlit | Free tier, quick to build, runs headless on Render. |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` | Local, no API key, 384-dim. Same model for chunks and questions. |
| Vector DB | ChromaDB (persistent client) | Git-ignored; rebuilt at build time on Render. |
| LLM | Groq, default `qwen/qwen3.8-27b` | Free tier; key in `.env`, never committed. **The id is already confirmed against the live Groq model list** — `llama-3.1-8b-instant` was retired, and the remaining `meta-llama/*` ids are prompt-guard classifiers, not chat models. Groq retires ids without notice, so re-check `c.models.list()` if a Phase 5 call starts failing. Keep it in `config.py` so switching is a one-line change. |
| Fetching | `requests` + `beautifulsoup4` | Public page fetch + text extraction. |
| Config/secrets | `python-dotenv` + `.gitignore` | `.env` stays local. |
| Deps | `requirements.txt` | Pinned, used by both local and Render. |
| Docs/data | `data/sources.csv`, `data/chunks.txt`, `README.md`, `samples/sample_qa.md` | Required deliverables. |

### Deployment note (Render free tier)

Render's free web service has an **ephemeral filesystem** and spins down when idle. Two decisions follow:

- **Git-ignore `data/chroma/`, rebuild it during the build.** Only `.gitkeep` is committed. The binary blobs are derived from `data/sources.csv`, so they are excluded the same way `data/raw/` is. This also keeps multi-hundred-MB SQLite churn out of every commit that touches the corpus.
- **Ingestion moves to the Render build command.** Because the free tier has an ephemeral filesystem, the store cannot survive a restart and cannot be read from git, so `python -m ingest.run_ingestion` runs as the second half of the build command. "Ingest once" is true per deployment rather than per repo.
- **Startup bootstrap stays as a fallback only.** `retrieval` still ingests when the collection is genuinely missing, but that path is not the plan.

Costs of this choice, stated so they are not discovered at deploy time:

- **The build now depends on third-party uptime.** It fetches every URL in `data/sources.csv` from sbimf.com, amfiindia.com and sebi.gov.in. `run_ingestion` exits non-zero if no documents load, or if any of the 7 demo facts is absent, so one changed official page shows up as a failed build.
- **The build needs more memory than the free tier has.** Loading `all-MiniLM-L6-v2` through sentence-transformers costs roughly 800 MB resident once torch is imported, and embedding ~2,700 chunks on CPU follows. 512 MB / 0.5 CPU is not enough; use a paid instance.

The sentence-transformers model is downloaded into the container on first run regardless (~90 MB), which lengthens the first cold start.

Build command `pip install -r requirements.txt && python -m ingest.run_ingestion`, start command `streamlit run app.py --server.port $PORT --server.address 0.0.0.0`, root directory left empty because `app.py` sits at the repo root. Set `GROQ_API_KEY` in the Render dashboard, not in the repo, and pin `PYTHON_VERSION` to 3.14 since there is no `.python-version` file to read.

## 6. How the PRD Success Criteria Map to the Design

| Success criterion | Where it is enforced |
|---|---|
| Exactly one citation per answer | `generator.py` prompt + `guardrails.py` post-check |
| ≤ 3 sentences | `generator.py` prompt + `guardrails.py` post-check |
| "Last updated from sources:" | App code appends it from the cited chunk's `fetched_at`. The LLM is explicitly told **not** to emit dates. |
| Refuse advice / performance / PII | `guardrails.py` pre-check short-circuits before any LLM call |
| Inspectable chunks + documented strategy | `ingest/chunker.py` → `data/chunks.txt`, section 2.3 of this doc |
| ChromaDB persisted, ingest once | `ingest/store.py` with persistent client |
| One local embedding model for both sides | `ingest/embedder.py` shared by ingestion and `retrieval.py` |
| Groq key in `.env`, never committed | `config.py` + `.gitignore` |
| Public official sources only | `config.ALLOWED_DOMAINS` enforced in `ingest/loader.py` (domain-level, see §2.4) |
